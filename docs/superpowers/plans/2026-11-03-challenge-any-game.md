# Challenge a friend on any game — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any eligible solo game can be sent as a challenge, the friend gets a golden-ticket invite and the exact same content, and both sides can save a brag image.

**Architecture:** Reuse the daily challenge's seeded launch in `FF.GameFlow` (js/registry.js) for challenge runs and for every challenge-candidate run, add a `config.sharedDeal` flag that games honour, upgrade `FF.Challenge` (js/social.js) to v2 links with a game id, and add `FF.ShareCard` (js/shareCard.js), a canvas card maker.

**Tech Stack:** Vanilla ES5-style classic scripts, no build; Node test harness `node tools/test/run.js` (tools/test/harness.js `loadFF`); Firebase RTDB rules generated by tools/gen-rules.js.

**Spec:** docs/superpowers/specs/2026-11-03-challenge-any-game-design.md

## Global Constraints

- Colours only from css/tokens.css; app screens use `FF.UI`; strings via `FF.t(key, fallback)` / the local `t`; sentence case; icons, no emoji in buttons.
- Eligible = `FF.Leaderboards.active(def)`; fair run = `FF.Leaderboards.unrankedReason(config)` is `null` or `'account'`.
- Standard settings = `FF.Leaderboards.standard()` (difficulty, length, timer, clock 0), one player.
- Link stays `#challenge=<base64url JSON>`; `v: 1` (quiz topic) keeps working; `v: 2` adds `g` (game id).
- A received challenge unlocks its game once: skip `FF.Access.canPlay` and `usePlay` for that run only.
- Guests: `FF.GameConfig` feature `challenge` stays account-only for sending; a guest can play a received link.
- Rules: challenge result score cap 1,000,000, `correct` optional, optional `game` string ≤ 40.
- Reduce motion: no count-up or confetti.
- New scripts go in play.html (after js/leaderboards.js / before js/social.js as needed) and tools/test-seed.html; bump `CACHE` in sw.js.

## Review Focus

1. A run that started as a normal solo game but the player changed settings mid-way (game clock, display mode) — no challenge button.
2. A v1 link from before this change — still opens the quiz-topic invite and plays.
3. A link for a game that's disabled or not in this version — friendly message, no crash.
4. Leaving the challenge game early — the points so far count, the reveal shows.
5. Share card with a photo avatar that fails to load or no cover art — falls back to initials / category wash, never throws.

### Task 3: `FF.Challenge` v2 — records, links, wording, rules

**Files:**
- Modify: `js/social.js` (`FF.Challenge`), `tools/gen-rules.js`, `database.rules.json` (only `challenges`)
- Test: `tools/test/social.test.js`, `tools/test/leaderboards.test.js` (rules)

**Interfaces:**
- Produces:
  - `FF.Challenge.fromRun(cur, results) -> rec` — saves `{ id, v: 2, game, seed, role: 'sent', at, me: { score, ms, correct?, stats } }` and posts it.
  - `FF.Challenge.link(rec) -> string` — v2 payload `{ v:2, i, s, g, n, a, sc, st }` (`st`: up to 3 `[value, label]` pairs); v1 records keep v1.
  - `FF.Challenge.decode(code) -> { id, seed, v, game|topic, from:{ name, avatar, score, correct?, stats } } | null` — v2 score clamp 0..1,000,000; unknown game id keeps `game` but `FF.Challenge.playable(c)` returns false.
  - `FF.Challenge.accept(id)` — v2: `FF.GameFlow.launch(game, { challenge: { id, seed }, skipIntro: true })`; v1: the existing QuizRun path.
  - `FF.Challenge.finishRun(cur, points, results)` — stores the received record (role `received`) and posts it.
  - `FF.Challenge.wording(id) -> { tagline: string, button: string }` — FNV-1a hash of the id picks from `TAGLINES` (≥ 6, each with `{name}`) and `BUTTONS` = Accept the challenge / Take them on / I'm in.
  - `FF.Challenge.stats(results) -> [{ value, label }]` — from `bestStreak`, `fastest`, `mostWords`, `quizCorrect`, max 3.

- [ ] Tests: v2 round trip (id, seed, game, score 250000, stats); v1 code from the existing test still decodes as a topic; tampered v2 score 5,000,000 clamps to 1,000,000; `wording('abc')` is the same twice and is in the sets; `wording` over 50 ids uses at least 3 taglines; the rules accept `{ name, score: 250000, t, game: 'memoryMatch' }` without `correct` and reject score 1,000,001.
- [ ] Run — fail. Implement; change `RESULT` in gen-rules.js; splice the new `challenges` validate into database.rules.json by hand (keep everything else).
- [ ] Run — pass. Commit `feat(challenge): v2 links for any game`.
