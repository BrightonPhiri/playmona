# Smaller Points Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every game scores in small points (no single award above 10), XP and leaderboards follow the new scale, and the boards restart as Season 1.

**Architecture:** Each game's numbers change where they live today (game file or shared `rules.js` that the server referees also load). A new test file, `tools/test/points.test.js`, sets each game's scoring at the edges of the new table. The platform then changes the pieces that depend on the scale: XP, leaderboard paths and caps, challenge caps, saved personal bests, and the rules text.

**Tech Stack:** Vanilla ES5 classic scripts (no build step), Node test harness (`tools/test/harness.js`, `node tools/test/run.js`), PHP 8 (`api/lib`), Firebase RTDB rules generated by `tools/gen-rules.js`.

**Spec:** `docs/superpowers/specs/2026-11-27-points-rebalance-design.md`

## Global Constraints

- No single award above 10. Costs and penalties are −1 to −3. Round and run totals may go above 10.
- No multiplier may push an award past 10. Difficulty sets a base inside 10 (Easy 6, Normal 8, Hard/Expert 10). Streaks add a flat bonus.
- Letter Rush (`js/games/letterRush.js` `points`) and WordFlow (`js/wordflow/rules.js`) do not change. Charades (`js/charades/rules.js` `points`: 1, or 2 with a twist) does not change.
- The Celebrations quiz and Celebrations Picture Rush (`js/celebrate/**`) do not change.
- SketchBack `MAX_POINTS` is drawing stroke data, not score. Leave it.
- Leaderboard cap: `MAX_SCORE = 1000` everywhere (JS, rules, PHP).
- New board rows carry `v: 2`. The rules require it on `leaderboards/<game>/s1/**`, `daily/<day>/<uid>` and `challenges/<id>/<uid>`.
- Work in the worktree `…/scratchpad/audit` on branch `feat/points-rebalance`, never in the OneDrive checkout (git fails there).
- Patch files with node scripts that throw when an exact match is missing, then `node --check <file>`. No inline `node -e` with regexes.
- Baseline on main 38eaa28: `node tools/test/run.js` → 1104 passed, 3 failed. The 3 already failing: "ch TV display", "ch timing", "wordshift data: the server copies match". Don't fix them here; no new failures allowed.

**Run one test file:** create `tools/test/one.js` in Task 1:
`node tools/test/one.js points` loads `tools/test/points.test.js` (plus any other names given) and runs it with `harness.run()`.

## Review Focus

1. **A phone still on the old page after the deploy** posts an old-scale score. Expected: the rules refuse it, because it has no `v: 2`. Pinned in Task 10 (rule strings contain the `v` check).
2. **A crew bot in a Bible Quiz room** scores with its own copy of the formula. Expected: bot points equal phone points on the new scale. Pinned in Task 1 (existing crew-match test kept, values new).
3. **Lots of hints, wrong taps or a slow finish.** Expected: never below 0, and Crossword never below its floor of 1. Pinned in Tasks 6 and 7.
4. **Endless runs (What's Missing? Endless, Remember the Sequence) going past 1,000.** Expected: the board saves 1,000 and the game still shows the real score. Pinned in Task 10.
5. **A player who opens the app twice after the update.** Expected: personal bests clear once only, and later bests are kept. Pinned in Task 11.
